## A day in the life

```console
$ kasl report
Report for August 8, 2026

+--------------+-------+-------+----------+
| ID           | START | END   | DURATION |
+--------------+-------+-------+----------+
| 1            | 09:12 | 13:30 | 04:18    |
| 2            | 14:18 | 16:02 | 01:44    |
| 3            | 16:29 | 18:04 | 01:35    |
|              |       |       |          |
| TOTAL        |       |       | 07:37    |
| PRODUCTIVITY |       |       | 96.1%    |
+--------------+-------+-------+----------+
```

You never started a timer or stopped one. The daemon has been watching activity since you logged in - `report` just asks it what the day looked like, and `report --send` files it.

## What kasl does

<CardGrid stagger>
	<Card title="Tracks itself" icon="laptop">
		A background daemon watches keyboard and mouse activity and turns it into
		workdays, work intervals and pauses. Nothing to start and stop by hand.
	</Card>
	<Card title="Collects your tasks" icon="list-format">
		Pulls today's GitLab commits and resolved Jira issues, keeps an inbox of
		assigned issues, and lets you add your own with tags and templates.
	</Card>
	<Card title="Files the report" icon="upload">
		Daily and monthly reports with productivity metrics, submitted to your
		corporate API with one command, or exported to CSV, JSON or Excel.
	</Card>
	<Card title="Reports to a team server" icon="cloud-download">
		Connect to a self-hosted [kasl-server](/reference/server/) and push a day
		whole - hours, pauses and tasks - with the offset that makes days from
		different time zones comparable. A week offline costs nothing: undelivered
		days are queued and the backlog goes in one request. Optional; kasl works alone.
	</Card>
	<Card title="Shows what leaves the machine" icon="seti:lock">
		Before a day goes anywhere, you can read exactly what would go.
		[`kasl server manifest`](/reference/server/#kasl-server-manifest) prints
		what the team server stores about you, in that installation's own words;
		[`kasl report --send --show`](/reference/report/#what-gets-sent) prints
		the payload the corporate API would receive, and sends nothing.
	</Card>
	<Card title="Stays out of the way" icon="approve-check">
		Single binary, no runtime dependencies, credentials in the OS keyring.
		Windows, macOS and Linux.
	</Card>
</CardGrid>
