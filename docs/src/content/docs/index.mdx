## A day in the life

```console
$ kasl report
Report for August 8, 2026

+--------------+-------+-------+----------+
| ID           | START | END   | DURATION |
+--------------+-------+-------+----------+
| 1            | 09:12 | 13:30 | 04:18    |
| 2            | 14:18 | 16:02 | 01:44    |
| 3            | 16:29 | 18:04 | 01:35    |
|              |       |       |          |
| TOTAL        |       |       | 07:37    |
| PRODUCTIVITY |       |       | 96.1%    |
+--------------+-------+-------+----------+
```

You never started a timer or stopped one. The daemon has been watching activity since you logged in - `report` just asks it what the day looked like, and `report --send` files it.

## What kasl does

<CardGrid stagger>
	<Card title="Tracks itself" icon="laptop">
		A background daemon watches keyboard and mouse activity and turns it into
		workdays, work intervals and pauses. Nothing to start and stop by hand.
	</Card>
	<Card title="Collects your tasks" icon="list-format">
		Pulls today's GitLab commits and resolved Jira issues, keeps an inbox of
		assigned issues that rules pin, hide and tag by themselves, and lets you
		add your own with tags and templates. Taking and finishing an issue can
		move it in Jira too.
	</Card>
	<Card title="Files the report" icon="upload">
		Daily and monthly reports with productivity metrics, submitted to your
		corporate API with one command, or exported to CSV, JSON or Excel.
	</Card>
	<Card title="Reports to a team server" icon="cloud-download">
		Connect to a self-hosted [kasl-server](/reference/server/) and push a day
		whole - hours, pauses and tasks - with the offset that makes days from
		different time zones comparable. A week offline costs nothing: undelivered
		days are queued and the backlog goes in one request. Turn on the
		[pulse](/reference/server/#kasl-server-pulse) and the team dashboard shows
		whether you are working right now - the state only, and only if you
		choose to. Optional; kasl works alone.
	</Card>
	<Card title="Shows what leaves the machine" icon="seti:lock">
		Before a day goes anywhere, you can read exactly what would go.
		[`kasl server manifest`](/reference/server/#kasl-server-manifest) prints
		what the team server stores about you, in that installation's own words;
		[`kasl report --send --show`](/reference/report/#what-gets-sent) prints
		the payload the corporate API would receive, and sends nothing.
	</Card>
	<Card title="Answers scripts, too" icon="seti:json">
		`--json` on every command that prints data - the day, the month, tasks,
		the inbox, the server connection - as one document on stdout, for a
		status bar or a script. `--plain` keeps the output for logs and `grep`:
		no colour, no emoji, tables as tab-separated lines. `NO_COLOR` is
		honoured. See [kasl in scripts and CI](/guides/scripting/#json-for-programs).
	</Card>
	<Card title="Talks to your assistant" icon="puzzle">
		[`kasl mcp`](/reference/mcp/) serves the day, the week, tasks and the
		inbox to a coding assistant such as Claude Code over MCP - read-only, the
		same documents `--json` prints, and connected only when you connect it.
	</Card>
	<Card title="Takes plugins" icon="setting">
		A program named `kasl-plugin-*`, in any language, hears the day end and
		the report go out, runs on a day or an issue by hand, or feeds the inbox
		beside Jira. [`kasl plugin`](/reference/plugin/) lists them and sets them
		up; [Writing a plugin](/guides/writing-a-plugin/) is the protocol.
	</Card>
	<Card title="Stays out of the way" icon="approve-check">
		Single binary, no runtime dependencies, credentials in the OS keyring.
		Windows, macOS and Linux.
	</Card>
</CardGrid>
